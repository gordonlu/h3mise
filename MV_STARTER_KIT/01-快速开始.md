# 从歌曲到第一组镜头

## 1. 启动工作台

完整下载并解压 H3Mise，安装含 npm 的 Node.js 22.13 或更新版本。Windows 双击根目录 `start.bat`；macOS 打开 `start.command`；Linux 运行 `sh start.sh`。首次启动会准备依赖和网页，使用期间保持启动窗口打开。

视频处理还需要 FFmpeg 与 FFprobe。在设置里的环境检查确认二者可用。仅阅读、规划故事可以先不安装视频工具。无 Key 时可以先用 Mock 示例熟悉流程；Mock 不代表真实模型的画质或嘴型效果。

## 2. 准备自己的素材

| 素材 | 要求 |
| --- | --- |
| 完整歌曲 | 最终混音母版，后期作为连续原曲使用 |
| 原歌词 | 正确文字来源；保留每段的音乐时间范围 |
| 干人声 | 用于演唱驱动；优先来自原曲分轨，保持原唱速度 |
| 人物参考 | 清楚的单人身份与服装参考 |
| 环境参考 | 对应故事地点，能交代布局、光向和空间 |

先填 [项目制作表](05-项目制作表.md)。用一句话说明主角要完成什么、途中做出什么选择、结尾发生什么变化。情绪需要通过可见行动展开。

## 3. 配置生成服务

在设置中先选择 RunningHub 中国大陆或 Global 站点，再输入同站点自己的 API Key。Key 只在本机设置页填写。

按 [工作流指南](02-RunningHub工作流.md) 分别添加普通叙事和音频锁定演唱两个 App，保存、检测节点、检查预览载荷。每个 App 保留自己的映射。

## 4. 在 H3Mise 建立项目

新建故事项目，填写歌曲长度、画幅和视觉风格。在资产页导入人物、场景、干声片段；建立角色/场景及对应参考。按故事段落建立 StoryBeat，再建立 Shot。Storyboard 生图是可选的，可以先跳过。

Shot 是计划，Take 是生成结果。每个镜头写清时间范围、动作、景别、机位、参考和离场状态，再保存导演计划和提示词版本。

## 5. 先通过两个真实小样

先做一条人物有具体动作的叙事镜头，再做一条完整短乐句的演唱镜头。叙事采用人物与环境参考；演唱按 [演唱指南](03-演唱提示词.md) 绑定唯一完整干声。

对准确提示词版本运行 Preflight；核对 App、素材、时长、比例、MP 和费用后，按当前用户授权提交。无需为测试连接而提交付费任务。样片成功后量实际宽高、帧率和长度，并连续审看画面、嘴型与原音轨。

以目标 1920×1080 为例，先确认工作流与 H3Mise 映射都支持它，再看实际文件。界面中的“16:9”“1MP”不等于 1080p；当前两套参考配置不能据此承诺原生 1080p。不满足时先调整接入方案或明确接受的交付尺寸，再继续批量生成。

## 6. 按故事推进整片

先铺完整故事覆盖，再补关键演唱和细节。长句可以完整长镜头承接，也可以部分不出镜唱；不必每句都对脸。切换地点、景别和行动，让每个镜头带来新信息。

有授权且下一镜头已准备好时，空闲槽位先提交，再审已有产物。共享账号的运行与本地排队合计建议最多 2 个，账号限制更低时按更低限制。已通过的 Take 保留，修改另存新版本。

最后保留无字母版、加歌词和片头片尾、检查手机可读性，记录实际扣费，并保存当前交接。详见 [审片与交付](06-审片与交付.md)。
