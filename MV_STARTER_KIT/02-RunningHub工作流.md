## 在设置中登记

1. 选择站点并填写自己的 Key。
2. 在 RunningHub App 列表中添加一项，填写名称和 App ID，点击保存。
3. 对该项点击“检测节点”，核对提示词、图像、音频、时长和尺寸字段。
4. 用“预览载荷”检查实际映射。检测只是读取节点，不会生成视频。
5. 普通叙事默认设为当前；做演唱前将音频锁定项设为当前，采用 `ref2va` 并检查对应输入。必要时提交后恢复叙事项。已有任务依自己的请求快照执行。

`nodes_detected` 表示发现了节点；`verified` 表示真实提交返回过任务号；二者都不代表成片或嘴型通过。

核对时支持 `t2va / ref2va / vref2va`。这些 image 是普通参考槽，不能当作字面首帧或尾帧。真正首尾帧模式需要独立 Frame App 及真实对应端口。

## 音频锁定对口型 App 参考映射

| 业务输入 | nodeId.fieldName | 说明 |
| --- | --- | --- |
| 提示词 | `250.prompt` | 使用 [同步基线](03-演唱提示词.md) |
| 人物参考 | `231.image` | 必填，对应 `<Picture 1>` |
| 环境参考 | `232.image` | 可选，对应 `<Picture 2>` |
| 唯一原干声 | `247.audio` | 对应 `<Audio 1>`，完整连句且不超过 14 秒 |
| 比例 | `115.aspect_ratio` | 横版枚举为 `16:9 (Widescreen)` |
| MP | `115.megapixels` | 按 App 和 H3Mise 当前支持值设置 |

**没有外置 duration 节点，没有参考视频槽，也没有首尾帧槽。音频实际长度控制生成时长。** 不要从叙事 App 复制 `222.value`，也不要用 Shot 默认秒数补静音或拉伸干声。核对时声明模式为 `t2va / ref2va`；演唱采用人物参考的 `ref2va`。

预检需确认已启用该工作流、仅绑定一个真实干声、人物与环境引用编号正确。App 没有接收的参数不应捏造映射。生成后量真实输出帧数；视频容器可能比音频略长，剪辑采用范围另记。

## 分辨率与费用

历史成功接入采用过 16:9 / 1MP，这不能当作已验证原生 1080p 的配方。当前 H3Mise 支持的 MP 预设与 App 原始节点可选范围也可能不同；不要绕过映射随意发送更大数值。先通过一个目标尺寸实测样片，再确定整片输出规格。

两项使用同账号 Key、共享并发。费用按实际扣费记录；价格、可用性与排队速度由远端服务决定。超时先查已有任务号，确认状态后再决定是否重试。
