# From Playable Clips to a Finished MV

## Separate the conclusions

| Observation | What it proves |
| --- | --- |
| A remote task ID is returned | The request was accepted |
| LOCAL_READY | The artifact was retrieved locally |
| Full decode, dimensions, and frame count are normal | The file is technically usable |
| A still frame looks normal | That moment looks normal |
| Watch the whole segment continuously | Only this checks motion, set stability, and character changes |
| Compare lip sync against the original song | Whether visible articulation, pauses, and phrase endings follow |
| The user approves | The corresponding version and adoption scope were accepted |

A successful response, audio correlation, ASR, or a still frame cannot replace a complete audio-visual review. Check especially phrase endings, the last second of a shot, background crowds, objects, and facial skin tone. Approved assets are not regenerated repeatedly because of an old plan.

## Editing and sound

Keep a version without titles and cover the whole piece continuously with the complete original song at original speed. Check and record the generated audio track separately; alignment to the original song is verified separately in post. Save the source frame, in-point, out-point, and speed actually used for each Take; avoid recording only "used this one."

Use the H3Mise timeline or your own editor to assemble. When editing externally, save a separate edit record and return the finished piece to H3Mise as media; importing media does not automatically create an in-app timeline export record. Do not regenerate because a pending count has not reached zero.

Transitions serve the story. A short dissolve can help when similar interior character shots cut harshly; you do not need an effect on every cut. Character action should show real progress; avoid an entire piece of slow motion and repeated face shots against the same background.

## Lyrics, opening, and ending

Use the original lyrics as the text source; ASR only helps locate lines. Check every line for missing words, repeats, and long-line breaks, and align to the actual singing. Choose fonts for both design and phone readability, and keep the font license; check actual font size, stroke, contrast, and safe margins on a roughly 375-pixel-wide screen.

Lock the timing of the opening, credits, and ending before laying out. When the user needs a demo, deliver a demo first; when the user has explicitly asked for a direct full-song output, do not add preview approvals. Whenever possible, finish the final titles in one pass from the clean version to reduce repeated encoding.

## Cost and submission

Record actual charges, currency, conversion basis, manual tasks, and whether failures were charged. Do not enter 0 for unknown costs; do not present a known subtotal as the total cost. In the end credits, state the actual division of labor for music, video, human work, and the Agent.

Prefer frames from the real finished video for the cover, and lay out landscape, 4:3, and 3:4 versions separately, keeping faces and the title readable on a phone. The title and description should accurately describe the work and how it was made; fill in the creation statement according to the publishing platform's current requirements.

## Wrap-up

Deliver the final video, the clean version, the subtitle source, the font license, the cover, the submission copy, the adoption record, and the current handoff. Check existing jobs and costs so no unexplained in-flight state remains.

When organizing an external project, keep input assets, review versions, deliveries, and evidence separate; do not directly move H3Mise's internal project media. Keep reusable methods in general documentation and keep the specific song, characters, task IDs, paths, and costs in that project's record.
