## 0. 一句话

把「故事 → 节拍 → Storyboard → 镜头 → Take → 时间线 → 导出」这条目前分散在 8 个页面里的链路，放进**一张可缩放的节点画布**（Studio）里完成：左侧取素材，中间看全局流程并连线，右侧就地编辑，底部看时间线与渲染队列。

参考对象：

- **MiniMax Design 的 Canvas Flow**：脚本、分镜、图像、视频、音频、剪辑在一张画布上，节点自动连接，从调研到成片不切工具。
- **ComfyUI**：类型化端口、带颜色的连线、节点库拖入、右键菜单、队列执行。

H3Mise 借鉴两者的**交互形态**，但保留自己的**产品模型**（见 §2）。

## 1. 设计原则

| # | 原则 | 含义 |
| --- | --- | --- |
| P1 | **画布是视图，不是第二份数据** | 节点 = 已有领域对象（StoryBeat、Shot、Take…）；连线 = 已有关系（`storyBeatId`、`dependsOnShotId`、ReferenceBinding、TimelineClip…）。画布只额外保存「位置、折叠、视口、便签」。删掉画布布局，项目数据零损失。 |
| P2 | **连线即操作，操作走原有 API** | 拖一根线 = 一次明确的领域修改（绑定参考、设置帧依赖、加入时间线）。服务端原有校验、幂等、原子性全部保留。 |
| P3 | **付费永远不隐式发生** | 改参数、连线、移动节点都**不会**触发渲染。任何付费动作（视频渲染、Storyboard 生图、单格重生、一键制作真实 Provider）必须经过统一的「费用确认」对话框。没有 ComfyUI 式的"改完自动排队"。 |
| P4 | **渐进披露** | 远看是流程全貌（状态色块），近看是卡片，再近才是可编辑字段；深度编辑在右侧 Inspector，复杂编辑可"在完整页面打开"。 |
| P5 | **一屏完成主链路** | 新手不离开 Studio 即可完成：Mock 渲染 → 选片 → 时间线 → 导出。设置页仍保留为独立页面（低频）。 |
| P6 | **键盘优先、可回退** | 所有画布操作有快捷键；左侧 Outline（大纲树）是画布的无障碍替代视图；旧页面在过渡期全部保留。 |
| P7 | **连续性优先于重试** | 画布要把"帧链"（上一镜尾帧 → 下一镜首帧）和"角色资产 → 镜头"画成最显眼的关系，引导用户用 `i2va` / `previous_take` 而不是纯文本抽卡。 |

## 2. 与 ComfyUI / MiniMax Design 的异同

| 维度 | ComfyUI | MiniMax Design | **H3Mise Studio** |
| --- | --- | --- | --- |
| 画布上的节点代表什么 | 计算算子（Loader、Sampler…） | 创作产物 / Agent 任务 | **作品的领域对象**（Beat、Shot、Take…） |
| 图是不是程序 | 是，整图提交执行 | 半自动，Agent 编排 | **否**。图是项目状态的可视化与编辑面板 |
| 执行方式 | Queue Prompt 执行整图 | Agent 并行执行 | **按节点显式执行**；批量走"一键制作"计划 + 确认 |
| 结果去向 | 输出节点覆盖预览 | 画布资产 | 每次生成**新增 Take**，永不覆盖 |
| 付费保护 | 无（本地算力） | 平台额度 | Preflight + 活动任务锁 + 费用确认，不可绕过 |
| 自由度 | 完全自由 | 中 | 自由摆放 + 强类型连线规则；非法连线不可落下 |

结论：**像 ComfyUI 一样操作，像 H3Mise 一样思考。**

## 5. 画布模型

### 5.1 泳道（Lanes）+ 行（Rows）

默认采用**「泳道布局」**：横向是生产阶段，纵向是叙事顺序。这比完全自由的 ComfyUI 画布更易读，也保证节点首次出现时有确定的位置。

```text
x →   L0 演员与场景   L1 故事   L2 节拍    L3 分镜     L4 镜头     L5 Takes    L6 剪辑/导出
y ↓
row1                Story     Beat 01   Panel 1-2   Shot 01    Takes(01)   Timeline
row2                          Beat 02   Panel 3     Shot 02    Takes(02)     │
row3                          Beat 03   Panel 4-6   Shot 03    Takes(03)   Export
```

- 行 = Beat 的 `order`。挂在某 Beat 下的 Shot 与该 Beat 同行起排；一个 Beat 多个 Shot 时向下展开占多行。
- 未挂 Beat 的 Shot 排在镜头泳道末尾的「未归属」分组。
- `L0 演员与场景` 是**纵向侧带**（Entity 节点），默认在画布最左；紧随其后的 `L0.5 素材` 泳道只放本集引用的媒体或用户钉住的媒体，避免媒体与实体叠在一起。
- 实体→镜头的 `cast` 连线默认可见；其他资产绑定仍以芯片 / 选中时显示为主（见 §7.5）。
- 泳道标题吸附在画布顶部（随横向平移，纵向固定），点击标题可"仅显示本泳道"。

### 5.2 自由布局

- 任何节点都可拖动；被拖动过的节点标记为 **pinned**（用户位置优先），之后"自动整理"不会移动它，除非选择"重置全部布局"。
- 视图菜单提供：`自动整理（保留手动位置）`、`重置为泳道布局`、`对齐到网格（16px）`。

### 5.3 分组与框

| 类型 | 来源 | 表现 |
| --- | --- | --- |
| Sequence 框 | 领域对象 `Sequence` | 半透明圆角框包住同一 Sequence 的 Beat 与 Shot；框标题可改名（写回 Sequence） |
| 便签 Note | 画布独有（仅布局数据） | 黄色便签，Markdown 纯文本，用于导演备注；不进入 Prompt |
| 自定义框 Frame | 画布独有 | 用户自建分组，仅视觉作用 |

### 5.4 一集一张画布

- 项目是系列工作区时，**每个 Episode 一张画布**（与现有 `activeEpisodeId` 作用域一致）。顶栏 Episode 切换 = 切画布。
- 实体（人物/场景）是项目级共享的，因此 L0 泳道在所有集里都会出现，但位置按集分别保存。

### 5.5 语义缩放（3 级 LOD）

| 缩放 | 级别 | 节点显示 |
| --- | --- | --- |
| < 0.45 | 概览 Overview | 只剩色块：序号 + 状态色 + 标题首字；连线变细；显示泳道大标题 |
| 0.45 – 0.9 | 卡片 Card（默认） | 缩略图、标题、关键参数徽章、状态、主操作按钮 |
| > 0.9 | 细节 Detail | 卡片 + 可就地编辑的字段（时长、模式、画幅、摘要），Prompt 前 3 行预览 |

## 6. 节点目录

通用节点结构（卡片级）：

```text
┌───────────────────────────────────────┐
│▌ 类型图标  标题                 ⋯   │  ← 头部：左侧 4px 类型色条；⋯ = 节点菜单
│  徽章：I2VA · 13s · 16:9 · ¥         │  ← 参数徽章；¥ 表示此节点有付费动作
├───────────────────────────────────────┤
│ ○ 输入端口                 输出端口 ○ │  ← 端口在两侧，带类型色与标签
│        [ 缩略图 / 摘要 ]              │
├───────────────────────────────────────┤
│ ● 状态文字           [主操作按钮]     │  ← 底部：状态 + 1 个主操作
└───────────────────────────────────────┘
```

### 6.1 故事节点 Story（L1，每集 1 个）

- 尺寸：280×200
- 输出：`beats`（TEXT，连到节拍泳道的总线）
- 主体：标题、梗概前 4 行、规划总时长、已覆盖时长进度条（Beat 时长和 / 规划时长）
- 主操作：`AI 拆解为 Beats`（AI；Agent 接管时变为"等待 Agent"）
- 菜单：`推荐叙事骨架…`、`套用骨架（3/6/9 段）…`（会提示"重整当前 Beats，不追加"）、`在完整页面编辑`
- 状态：草稿 / 已拆解 N 个 Beat

### 6.2 节拍节点 Beat（L2）

- 尺寸：240×120
- 输入：`story`（TEXT，隐式，来自 Story 总线）
- 输出：`beat`（BEAT）→ 镜头
- 主体：序号、标题、类别标签（铺垫/上升/高潮…）、时长、地点·时间·天气小字
- 主操作：无 Shot 覆盖时显示 `补齐 Shot`（免费，调用 materialize）；已覆盖时显示"→ 2 个镜头"
- 拖动排序：在 L2 内纵向拖动 = 重新排序 Beat（写回 order，确认后执行）

### 6.3 分镜页节点 Storyboard Page（L3，可选）

- 尺寸：320×(按 3/6/9 格自适应)
- 输入：`beats`（来自对应 Beat 区间，显示 `B01–B06`）
- 输出：每格一个 `IMAGE` 小端口（批准后才激活）
- 主体：3×1 / 3×2 / 3×3 缩略格；未生成时显示文字分格
- 动作：`准备文字分格`（免费）、`生成整页 ¥`、单格悬停 `重生此格 ¥`、`批准并接入镜头`（免费、幂等）
- 状态：draft / generating（进度环）/ ready / approved / failed
- 视觉提示：泳道标题标注「可选」，空泳道显示一句"可跳过，直接从节拍到镜头"。

### 6.4 实体节点 Entity（L0）

- 尺寸：160×180（头像为主）
- 输出：`entity`（ENTITY，按 kind 着色：人物/生物/场景/道具/载具）
- 主体：主图（缺主图时显示红色虚线框"缺主图"——这是连续性的前置条件）、名称、类型、CharacterState 数量
- 展开：点击 `▸ N 状态` 在下方展开 CharacterState 子卡片，每个子卡片有自己的 `IMAGE` 输出；默认折叠，避免状态与实体同级铺开
- 主操作：`上传主图`（缺图时）

### 6.5 媒体节点 Media（L0 或任意位置）

- 不默认全部上画布（素材可能上百）。出现规则：已绑定到本集某个镜头的媒体，或用户从左 Dock 拖到画布上的媒体。
- 输出：`IMAGE` / `VIDEO` / `AUDIO`
- 主体：缩略图 / 波形 / 时长
- 菜单：`提取帧`、`参考拉片`（P2 打开拆解节点）、`查看用途`

### 6.6 镜头节点 Shot（L4，核心）

- 尺寸：300×220（卡片），细节级 300×340
- 输入端口（左侧，自上而下）：
  - `beat`（BEAT）
  - `cast`（ENTITY，可多根；人物/生物 → 主角色，场景 → 场景）
  - `first_frame`（FRAME/IMAGE）
  - `last_frame`（FRAME/IMAGE，仅 `fl2va`/`l2va` 模式显示）
  - `refs`（IMAGE，多根；`ref2va`）
  - `video_ref`（VIDEO，仅 `vref2va` 显示）
  - `audio_ref`（AUDIO）
- 输出端口（右侧）：
  - `takes`（TAKE）→ Takes 节点（自动存在，不可手连）
  - `tail_frame`（FRAME）→ 下一个镜头的 `first_frame`（帧链）
- 主体：
  - 头部：`S02 指令演示完成获奖励`
  - 徽章：`I2VA` `13s` `16:9` `0.6MP` `¥`
  - 资产芯片：Olivia / Newton / 训练学校（缺失项红色"缺首帧"）
  - 缩略：Selected Take 海报帧，否则最新 Take，否则 Storyboard 格图，否则空态插画
  - 引导步骤点：`设计 ● 参考 ● 生成 ○ 选片 ○`（复用 `ShotGuideState`）
- 底部主操作（按状态切换，始终只显示一个）：

| 用户状态 | 主操作 | 是否付费 |
| --- | --- | --- |
| draft 待导演 | `AI 规划` | 否（AI） |
| ready 准备生成 · 无 Prompt | `编译 Prompt` | 否 |
| ready · 有 Prompt 未预检 | `预检` | 否 |
| ready · 预检通过 | `渲染 ¥` | **是 → 费用确认** |
| rendering | 进度环 + `查看任务` | — |
| review 待选片 | `选片` → 打开 Takes 节点 | 否 |
| done | `提交连续性` / 已完成 ✓ | 否 |

- 菜单：`运行到此处…`（见 §9.2）、`复制镜头`（P2）、`在导演台打开`、`删除镜头`（二次确认）。

### 6.7 Takes 节点（L5，每个 Shot 一个）

- 自动跟随 Shot（同行），不可单独删除。
- 尺寸：260×160；横向排列 Take 缩略（最多 4 个，更多显示 `+N`）
- 每个缩略：状态环（candidate 灰 / selected 绿 / rejected 删除线）、评分星、失败标签点
- 输出：`selected`（CLIP）→ 时间线（只有 Selected Take 有输出）
- 悬停缩略：0.5s 后自动静音预览视频
- 操作：`选择`、`拒绝`、`选择并提交连续性`、`导入外部视频为 Take`、`分析`、`AI 诊断`

### 6.8 剪辑节点 Timeline（L6）与导出节点 Export

- Timeline 节点：输入 `clips`（CLIP，多根，按时间线顺序编号）；主体为迷你胶片条与总时长；主操作 `快速组装`（免费，只用 Selected Takes）。
- Export 节点：输入 `timeline`；主体为最近一次导出的海报与时长；主操作 `导出`（本地 FFmpeg，免费但耗时，显示进度）。

### 6.9 画布独有节点

- **Note 便签**、**Frame 框**：见 §5.3。
- **Run Plan 计划卡**（临时）：点击"一键制作"后在画布右上浮出，列出将渲染的镜头，并在画布上高亮这些节点（见 §9.3）。

## 7. 端口类型与连线

### 7.1 端口类型与颜色

| 类型 | 含义 | 颜色（Light） | 形状 |
| --- | --- | --- | --- |
| TEXT | 故事文本 / Beat 总线 | `--text-3` 灰 | 圆 |
| BEAT | 节拍 | `--violet` | 圆 |

### 7.3 拖线时的反馈

- 开始拖线：所有**兼容**端口放大并发光，不兼容端口变灰 40%；不兼容节点整体降低不透明度。
- 悬停在兼容端口上：显示落下后的效果文案，例如「设为 S03 的首帧来源（previous_take）」。
- 悬停在不兼容端口：红色禁止光标 + 原因，例如「S01 在 S03 之后，帧链不能反向」「会形成循环依赖」「当前模式 T2VA 不接受首帧，先切到 I2VA」。
- 落在空白处：弹出**快速创建菜单**（ComfyUI 式）：从 Beat 拖出 → "新建镜头并连接"；从 Shot 的 `tail_frame` 拖出 → "新建下一镜头（I2VA，帧链）"。

## 9. 运行与付费确认

### 9.1 单节点运行

- 免费动作（AI 规划、编译 Prompt、预检、补齐 Shot、准备文字分格、快速组装、导出）：直接执行，节点显示 loading，完成后 toast。
- 付费动作（渲染、生成分镜页、单格重生）：**一律弹出费用确认**：

```text
┌ 确认付费生成 ─────────────────────────────────────┐
│ Provider    RunningHub（runninghub.cn）· verified  │
│ 镜头        S02 指令演示完成获奖励                  │
│ 模式        首帧生视频（I2VA）                      │
│ 参数        13s · 16:9 · 0.6 MP                     │
│ 参考        首帧：S01 尾帧 · 身份：Olivia, Newton   │
│ 预检        ✓ 通过（2 个警告，展开）                │
│ 预估费用    ¥ x.xx（来自 Provider Profile，仅供参考）│
│                                                    │
│ ⚠ 这会创建一个真实的 Provider 任务并产生费用。      │
│                        [取消]   [确认生成 ¥]        │
└────────────────────────────────────────────────────┘
```

- 规则：
  - Provider 为 Mock 时标题改为「确认生成（Mock，免费）」，无警告条，但**仍然显示参数摘要**以保持流程一致。
  - Profile 状态为 `unconfigured` / `failed` 时，确认按钮禁用并给出"去设置"链接。
  - `nodes_detected`（未经验证）时额外显示"首次真实提交，将用最低参数验证 Profile"提示。
  - 已有活动任务或候选 Take 时，确认框不出现，改为提示"先选片或对账"。
  - 确认按钮在对话框打开 600ms 内不可点击（防双击误触）。

### 9.2 运行到此处（Run to here）

在某个 Shot 上选择"运行到此处…"：

1. 计算上游链：该 Shot 的帧依赖链（`dependsOnShotId` 递归）中尚未完成的镜头。
2. 画布上高亮这些节点并编号执行顺序（①②③）。
3. 浮出计划卡：每个镜头的阶段（需要 Prompt / 需要预检 / 可渲染 / 等待依赖）。
4. 用户可先点「免费准备全部」（批量编译 Prompt + 预检），再点「确认渲染 N 个镜头 ¥」→ 合并费用确认框（列表形式）。
5. 依赖链上的下游镜头不会自动提交：上一镜出 Take 并被选中后，下一镜节点的主操作才变成"解析首帧 → 渲染 ¥"。

### 9.3 一键制作（顶栏）

- 点击 → 获取一键制作计划（已有接口），右上浮出 **Run Plan 卡片**，画布上将被渲染的镜头标为 `①…⑨`，**会被新建的镜头（来自未覆盖 Beat）以虚线幽灵节点显示**，确保用户看到真实任务数。
- 有候选 Take 或活动任务时，计划卡顶部红条阻塞："S02 有 2 个候选未选片"，点击定位。
- 确认框文案：「将创建 N 个镜头、提交 M 个渲染任务（Provider · 0.6 MP）」。

### 9.4 运行中反馈

- 节点进度环（来自 SSE `render.job.*`）；底部 Dock「队列」标签数字。
- 失败：节点红色边框 + 错误阶段 + Provider 任务 ID（可复制）+ `对账` 按钮（有任务 ID 时）而非"重试"作为首选。
- 成功：Takes 节点出现新缩略，带 "NEW" 角标；Shot 状态变为 review。

## 13. 关键流程走查

### 13.1 新手（Mock，零成本）

1. 项目页 → 安装 Good Boy Demo → 自动进入 Studio，画布按泳道展开。
2. 顶栏 Provider 芯片显示 `● Mock`，旁边说明"离线演示，不产生费用"。
3. 空选中时 Inspector 显示"下一步：为 S03 设计镜头"→ 点击即选中 S03 并打开导演计划。
4. S03 主操作依次变为 `AI 规划 → 编译 Prompt → 预检 → 渲染（Mock）`。
5. 出 Take → 在 Takes 节点点"选择并提交连续性"。
6. 底部时间线点 `快速组装` → `导出`。全程未离开 Studio。

### 13.2 从故事开始（主题故事，连续性优先）

1. 新建项目 → 空画布模板"从故事开始" → 故事节点处于编辑态。
2. 写梗概 → 故事节点 `推荐叙事骨架` → 套用 6 段 → 节拍泳道出现 6 个 Beat。
3. **画布提示条**："先建立主角资产再设计镜头可以保持角色一致"→ `新人物` 拖入 L0 → 上传主图。
4. Beat 上 `补齐 Shot` → 镜头泳道出现 6 个 Shot（最小导演计划已生成）。
5. 从 Olivia 节点拖线到 S01 的 `cast`；S01 的 `tail_frame` 拖到 S02 的 `first_frame`（帧链），依次连好。
6. S06 "运行到此处" → 免费准备全部 → 确认渲染 S01（帧链上只有首个可立即渲染）。

### 13.3 参考图镜头（Ref2VA）

1. 从资产 Dock 把两张图拖到 S04 的 `refs` 端口 → 角色选择浮层分别选"身份""环境"。
2. 若 S04 是 T2VA，落线时提示"切换为参考图模式（Ref2VA）？"→ 确认后模式改变，端口重新布局。

1. 外部 Agent 调用 `POST /api/ai/agent/session` → 顶栏 🤖 亮起"Agent 已接管推理"。

## 15. 视觉规范

- 全部颜色、圆角、阴影、字体引用 `web/src/style.css` 的现有 token（`--accent`、`--line`、`--radius`、`--shadow-1`…），Light/Dark 双主题自动适配。
- 画布背景：`--bg` + 24px 点阵（复用 `DotField` 风格，缩放时点阵不缩放密度）。
- 节点：`--bg-2` 底、`--radius-sm`（10px）圆角、`--shadow-1`；左侧 4px 类型色条：

| 节点 | 色条 |
| --- | --- |
| Story / Beat | `--violet` |
| Storyboard | `--info` |
| Entity / Media | `--ok` |
| Shot | `--accent` |
| Takes | `--warn` |
| Timeline / Export | `--text-2` |
| Note | `#F4D35E` |

- 字体：节点标题 13px/600；徽章 11px；正文 12px；等宽信息（任务 ID、节点 ID）用 `--mono`。
- 动效：节点进入 160ms 淡入+上移 4px；连线落下 120ms 描边闪烁；rendering 呼吸描边 1.6s 循环；尊重 `prefers-reduced-motion`（关闭所有循环动画）。
- 图标：沿用 `AppSidebar` 的 24×24 描边图标风格。

## 16. 无障碍与国际化
